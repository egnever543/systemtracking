Documentação

Tudo que você precisa saber para usar o WA CAPI Tracker.

1. Como funciona

O sistema conecta o clique no botão do WhatsApp com a venda que acontece na conversa, permitindo enviar um evento Purchase ao Facebook com o fbclid original do anúncio.

1

Visitante acessa a página vindo de um anúncio do Facebook com fbclid na URL.

2

Clica no botão do WhatsApp cujo link aponta para a URL de rastreamento.

3

Sistema registra o clique — salva o fbclid, IP e user-agent, gera um ID único como WA-8F3K2P e dispara um evento Lead ao Facebook CAPI.

4

Visitante é redirecionado ao WhatsApp com a mensagem pré-preenchida contendo o ID, ex: "Olá, vim pelo anúncio [WA-8F3K2P]".

5

Venda acontece e o vendedor vê o ID na primeira mensagem do cliente.

6

Vendedor registra a venda informando o ID e o valor. O sistema envia um evento Purchase ao Facebook CAPI com o fbclid original, fechando o ciclo de atribuição.

2. Configurar um site

Acesse Sites → Novo Site e preencha os campos:

Nome Identificação interna (ex: "Loja Principal").
Domínio Apenas referência visual, não valida a origem das requisições.
WhatsApp Número padrão com DDI+DDD sem espaços (ex: 5511999990000). Usado se nenhum número A/B for cadastrado.
Mensagem Texto pré-preenchido no WhatsApp. O ID de rastreamento é adicionado automaticamente entre colchetes ao final.
Pixel ID ID do seu Pixel do Facebook. Encontrado em Gerenciador de Eventos → seu Pixel → Configurações.
Token da API Token de acesso do sistema para a CAPI. Gerado em Gerenciador de Eventos → Conversions API → Gerar token.
Cód. de teste Opcional. Quando preenchido, eventos vão somente para a ferramenta Testar Eventos do Facebook, sem afetar dados reais. Remova em produção.

3. Link de rastreamento

O link de rastreamento fica na página de detalhes de cada site. Ele tem o formato:

https://seudominio.com/r/{siteId}

Ao ser acessado, o servidor automaticamente:

  1. Registra o clique com todos os parâmetros da URL
  2. Dispara um evento Lead ao Facebook CAPI em segundo plano
  3. Redireciona o usuário para o WhatsApp com o ID no texto
Importante: coloque este link diretamente no href dos seus botões. Funciona em todos os dispositivos, incluindo iPhone (iOS Safari).

Se o visitante não vier com parâmetros de anúncio (tráfego orgânico), o redirecionamento funciona normalmente — apenas sem dados de atribuição.

4. Snippet (opcional)

Necessário apenas se o fbclid não estiver diretamente no link de rastreamento — por exemplo, quando o link de destino do anúncio aponta para a página do seu site, não para o link de rastreamento.

Cole antes do </body> da página:

<script src="https://seudominio.com/tracker.js" data-site="{siteId}" async></script></code>

O snippet lê os parâmetros da URL da página (fbclid, gclid, utm_* etc.) e os adiciona automaticamente a todos os links de rastreamento presentes na página.

5. Distribuição A/B de números

Cadastre múltiplos números de WhatsApp por site com um peso para cada um. O tráfego é distribuído aleatoriamente de forma proporcional ao peso.

Número Peso % do tráfego
Vendedor A 70 70%
Vendedor B 30 30%

Se nenhum número A/B for cadastrado, o sistema usa o número padrão do site. A página de detalhes do site mostra cliques, conversões e taxa de conversão por número.

6. Registrar uma venda

Quando a venda ocorre, o cliente terá enviado na primeira mensagem algo como:

"Olá, vim pelo anúncio e quero saber mais! [WA-8F3K2P]"
  1. 1 Acesse Registrar Venda no menu superior.
  2. 2 Digite o ID (ex: WA-8F3K2P). O sistema mostrará os dados do clique original, incluindo se há fbclid.
  3. 3 Informe o valor da venda e a moeda (padrão: BRL).
  4. 4 Clique em "Registrar Conversão no Facebook". O evento Purchase é enviado ao CAPI com o valor e o fbclid original.
Cada ID pode ser convertido apenas uma vez. Tentativas de converter o mesmo ID novamente serão bloqueadas.

7. Integração Facebook CAPI

O sistema usa a Conversions API (CAPI) do Facebook para enviar eventos diretamente do servidor, sem depender de cookies ou bloqueadores de anúncio no navegador do usuário.

Eventos enviados

Lead Disparado no clique do link de rastreamento. Usa event_id: lead_{ID} para não colidir com o Purchase na deduplicação.
Purchase Disparado ao registrar a venda. Inclui o valor e moeda. Usa event_id: {ID} para evitar contagem duplicada se o evento for enviado mais de uma vez.

Dados de correspondência enviados

  • fbc — formado a partir do fbclid capturado no clique (permite o Facebook identificar o usuário e o anúncio).
  • client_ip_address — IP do visitante no momento do clique.
  • client_user_agent — navegador do visitante.
  • event_source_url — URL da página de origem do clique.

Onde verificar os eventos

Os eventos aparecem em Gerenciador de Eventos → seu Pixel → aba "Visão geral". Acesse a aba correta — a aba "Eventos de teste" só mostra eventos enviados com um código de teste ativo.

8. Perguntas frequentes

Funciona no iPhone (iOS / Safari)? ▼

Sim. O redirecionamento é feito pelo servidor via HTTP 302, que o iOS Safari segue normalmente como qualquer link. Não é necessário JavaScript para o redirecionamento funcionar.

E se o cliente vier sem fbclid (tráfego orgânico)? ▼

O clique é registrado normalmente e o redirecionamento funciona. Ao registrar a venda, o evento Purchase é enviado sem o campo fbc. O Facebook recebe o evento, mas sem match com um clique de anúncio — a conversão não será atribuída a uma campanha.

Enviei a venda (verde) mas não aparece no painel do Facebook. ▼

Verifique em ordem:

  1. Está na aba "Visão geral", não em "Eventos de teste".
  2. O campo Código de evento de teste está vazio nas configurações do site — se preenchido, os eventos só aparecem na ferramenta de teste.
  3. Aguarde alguns minutos — pode haver um pequeno delay no processamento.
Captura parâmetros do Google Ads (gclid)? ▼

Sim, o gclid é salvo junto com todos os outros parâmetros de clique. O envio para a API de conversões do Google Ads ainda não está implementado — apenas o Facebook CAPI é suportado atualmente.

Posso usar o mesmo Pixel em vários sites? ▼

Sim. Basta configurar o mesmo Pixel ID e Token em cada site. Todos os eventos chegarão no mesmo pixel, diferenciados pela event_source_url de cada clique.

O ID de rastreamento não apareceu na mensagem do cliente. ▼

Isso ocorre quando o cliente edita a mensagem pré-preenchida antes de enviar. O clique ainda é registrado no sistema — só não é possível associar aquela conversa específica ao evento de clique.
